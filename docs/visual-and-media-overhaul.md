# Visual and real-media overhaul — 8 October 2026

The previous organization remains, with a new editorial visual system throughout: warm ivory, dark ink, rust actions, bundled Fraunces and Manrope fonts, consistent smaller corner radii, fine borders and quieter navigation. Today now uses a real photograph from the day's session, with its source and a direct link to that exercise's form guide. New installs default to light; existing theme preferences remain intact. Installed-app icons and browser theme colors match.

Generated exercise illustrations no longer appear as instructional media or list thumbnails. Real creator thumbnails and the licensed photo set serve the session, library, physical therapy board and muscle pages. The anatomical body map remains separate. The catalog includes 82 video mappings and 69 pairs of photographs; all five entries without either are cardio or composite mobility blocks. Video metadata endpoints and all 138 image responses were checked. This is distinct from full playback verification: the audit records representative in-app playback checks for Pallof press, suitcase carry and bird dog, and direct playback/visual inspection for the cross-body cable extension. Other mappings retain their explicit playerChecked status.

The official Vimeo player loads only after Play. A failed load offers available photographs, written cues, retry and the creator link. Related variations are labeled before playback. In particular, pelvic tilt alone does not demonstrate the PDF's combined shoulder-flexion movement. Supine marches use a short, labeled pelvic-tilt variation. Photographs show two labeled positions instead of a simulated animation. Original photo URLs, license and attribution are retained; copies ship locally. No video is downloaded or cached.

The first-install service-worker cache now includes a build-generated manifest of code, styles, fonts and the body model as well as the photographs. It retains Daylight-only cache cleanup and does not intercept video-provider requests or other sites' paths. Application data and backups keep the existing storage key and schema. Keyboard focus stays inside the exercise guide and returns to the opener on close.

Validation: type check, 50 domain/media/offline tests, production Pages build, desktop and 390px phone review, main-screen width and image checks, and focused workout playback. With the local server stopped, the production app reloaded and its real exercise photograph remained available. A fresh installation also loaded and rendered the turning body model for the first time with its server stopped. The release fingerprint changes with code, photograph or body-model contents; a regression test covers this update path. Videos still require a connection. Existing build warnings about the large lazy body-view chunk remain; the chunk is included in the offline asset manifest.

Changes are prepared on the existing source and publication review branches. Production is unchanged until the publication pull request is merged.
